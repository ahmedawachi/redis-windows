Up and running in 60 seconds

  1. Download

    Redis-<version>-Windows-x64-msys2-with-Service.zip from Releases.

  2. Unblock and unzip

    Right-click the zip → Properties → tick Unblock → OK, then extract it anywhere. Unblocking first stops Windows SmartScreen from asking about every file. Avoid folders named bin or usr.

  3. Double-click RedisService.exe

    A window opens and Redis runs on 127.0.0.1:6379. It shows where your data is saved and how to connect. If something is wrong, such as port 6379 already in use, the window stays open and says why.

  4. Try it

    Double-click redis-cli.exe and type PING → PONG.

    127.0.0.1:6379> PING
PONG

  5. Stop it

    Press Ctrl+C, or close the window. Redis saves and shuts down cleanly. Closing the window gives it a few seconds, which is plenty for a development dataset; use Ctrl+C for a big one.

Out of the box Redis listens only on this machine (127.0.0.1), so nothing is exposed to the network.

Run it in the background, starting with Windows

Move the folder somewhere permanent, such as C:\Redis, and double-click install-service.bat. It asks for admin rights, installs the Redis service with its data in the data folder next to it, and starts it.

uninstall-service.bat removes the service again and keeps your data.

Check the service with:

sc query Redis

Production installs

For production, start from conf/redis.windows-cache.conf, a commented, production-minded config for cache workloads, and set a password.

Install with your own config and folders from an elevated prompt:

C:\Redis\releases\8.10.2-fork.1\RedisService.exe install --service-name Redis -c C:\Redis\conf\redis.conf --dir C:\Redis\data

Run it in a console with explicit options:

RedisService.exe run --foreground -c C:\Redis\conf\redis.conf

The first Ctrl+C stops Redis gracefully; a second forces it. RedisService.exe --help lists every option. Some of the useful ones:

OptionMeaning
--virtual-accountRun as NT SERVICE\<name> instead of LocalSystem and grant it access to the data, log and config folders. Opt-in; LocalSystem stays the default for compatibility.
--delayed-startDelayed automatic start (requires --start-mode auto).
--restart-policyon-crash|always|never. on-crash (default): restart redis-server after a crash; a clean exit the wrapper did not ask for (for example a client SHUTDOWN) stops the service.
--max-restarts N / --restart-window TCrash-loop cap (default 5 in 10m). When exceeded the service stops with exit code 1067 so the SCM recovery actions take over.
--health-interval T / --health-failures NLiveness PING (default every 5s; 12 misses = restart).
--stop-timeout TGraceful shutdown budget (default 120s).
--auth-password-file FILEPassword for the wrapper's own connections, if it must differ from requirepass.

Setting up a production server? Follow the admin guide: download to production in one path, with every command and a sign-off checklist.

Upgrades and rollbacks install side by side from another versioned folder and keep the previous version on disk; see the operations guide for the recommended layout, upgrades, monitoring and the incident checklist.

Running redis-server.exe directly

RedisService.exe converts paths for you. If you start redis-server.exe yourself, command-line paths use the runtime's format:

redis-server.exe /cygdrive/c/Redis/conf/redis.conf --dir /cygdrive/c/Redis/data

Inside redis.conf, Windows paths with forward slashes work: dir C:/Redis/data. The zip without the service also has start.bat, which runs Redis with the bundled redis.conf.

FAQ

Windows SmartScreen asks about every file

Unblock the zip before extracting it: right-click → Properties → tick Unblock → OK. If you already extracted it, clear the "downloaded from the internet" marker on the folder from PowerShell:

Get-ChildItem C:\Redis\releases\8.10.2-fork.2 -Recurse | Unblock-File
The window says port 6379 is already in use

Something else is already listening on the port, often another Redis. If you installed the service earlier with install-service.bat, it runs on 127.0.0.1:6379 and starts with Windows; check it with sc query Redis, or remove it with uninstall-service.bat, which keeps your data. The window stays open and says why it could not start, so nothing fails silently.

Why must the folder not be called bin or usr?

The MSYS2 runtime treats the folder two levels above the folder that holds msys-2.0.dll as its root /, and maps /bin to <root>\usr\bin (Cygwin: one level above). Unzip a package into a folder named bin or usr (for example C:\bin\Redis-...) and Redis cannot find its own config: can't open config file /bin/.... For the same reason, with C:\Redis\releases\<version>\ as the release folder, never create C:\Redis\bin, C:\Redis\usr or C:\Redis\etc\fstab.

Where is my data saved?

When you double-click RedisService.exe, the window shows where your data is saved when Redis starts. The service that install-service.bat creates keeps its data and log in the data folder next to it, and uninstall-service.bat leaves that folder in place.

For your own installs, pass --dir to RedisService.exe install, or set dir in redis.conf with an absolute Windows path and forward slashes, such as dir "C:/Redis/data". Keep config, data and logs outside the versioned release folders, so an upgrade or rollback only swaps binaries.

Old keys coming back after a restart with save ""? A leftover dump.rdb in dir is loaded at every startup and never rewritten. Stop the service, delete or rename it, and start it again.
